# Market desk

The multi-agent system behind the home page's **Market watch**: upcoming market-moving events with an
up/down call and a probability for the Dow, Nasdaq and S&P 500, each call scored against the close.
Python 3.11+. The standard library is enough locally (SQLite); PostgreSQL needs `psycopg[binary]`.
Product overview: [the repository README](../README.md#market-watch). Design: [DESIGN.md](DESIGN.md).

## Run locally

```bash
cd market
python -m desk run                 # one refresh: coordinator + 4 worker threads; writes ../site/data/market/timeline.json
python -m http.server 8088 -d ../site
```

The analyst calls `qwen3.7-plus` through the Qwen Token Plan's OpenAI-compatible API (a reasoning model:
about 200 s and ~75K tokens per refresh). It reads `QWEN_LLM_API_KEY_V2` from
the environment, or from the dotenv file named by `DESK_ENV_FILE` (default: `../../.ENV`, i.e.
`E:\repos\.ENV`). Without a working key it uses the rules baseline and says so on the page.

| Variable | Default |
|---|---|
| `DESK_LLM_BASE_URL` | `https://token-plan.maas.qianwenaiapi.com/compatible-mode/v1` |
| `DESK_LLM_MODEL` | `qwen3.7-plus` (the plan also lists `qwen3.7-max`, `qwen3.6-flash`, `deepseek-v4-pro`) |
| `DESK_LLM_USD_IN` / `DESK_LLM_USD_OUT` | `0` (prepaid plan; set per-1M-token prices for a metered endpoint) |
| `DESK_WINDOW_DAYS` | `14` |
| `DESK_DB` | `market/var/desk.sqlite3`, or a PostgreSQL DSN `postgresql://user:pass@host:5432/db` |
| `DESK_PUBLISH_DIR` | `site/data/market` |

## Run as services

```bash
python -m desk coordinator         # schedule, wake-ups, planning; one instance
python -m desk worker              # as many as you like; --roles analyst,critic to specialise
```

## Operate

```bash
python -m desk status              # recent missions
python -m desk explain <mission>   # what each agent did, why, and what happens next
python -m desk metrics             # completion, success, recovery, retries, cost, human interventions
python -m desk escalations
python -m desk approve <mission>   # release a publish that verification held back
python -m desk resolve <id> --action retry|skip|accept
python -m desk intents             # intents, agents, tools
```

## Database

All durable state lives in one database: missions, the task graph and its queue, the event log,
artifacts, checkpoints, idempotency records, locks, escalations, timers, long-term knowledge and usage.

| Where | Backend |
|---|---|
| local runs and tests | a SQLite file (WAL) |
| k8s (`market` namespace) | **PostgreSQL 16** (`desk-pg` StatefulSet, 2 Gi node-local volume) |

Both run the same SQL. On Postgres every write transaction takes one advisory lock, which serialises
writers the way SQLite's `BEGIN IMMEDIATE` does, so a task can never be claimed twice. The schema is
created on first start. Its password is generated on the node at first deploy and never leaves it.

To try Postgres locally:

```bash
docker run -d --name desk-pg -e POSTGRES_DB=desk -e POSTGRES_USER=desk -e POSTGRES_PASSWORD=change-me   -p 127.0.0.1:55432:5432 postgres:16-alpine
DESK_DB=postgresql://desk:change-me@127.0.0.1:55432/desk python -m desk run
```

## Evaluate

```bash
cd market && python -m unittest -v                                   # on SQLite
DESK_TEST_PG=postgresql://desk:change-me@127.0.0.1:55432/desk   python -m unittest -v                                              # the same 27 cases on Postgres
```

27 cases, no network: recorded source shapes, a fake clock and a fake model. With `DESK_TEST_PG`
every test starts from empty tables in that database, so point it at a throwaway one.

## Deploy

```bash
market/deploy/release.sh            # build arm64 → ECR heros-market → apply market/deploy/k8s/market.yaml by digest
market/deploy/release.sh --dry-run  # server-side dry run
```

It uses `INSTANCE` from `deploy/deploy.env` and `deploy/ssm.sh`, like the landing page's release. It needs
the AWS CLI signed in, Docker with `buildx`, and a clean, committed tree (the image is tagged with HEAD).

| In `market` | What |
|---|---|
| `desk-pg` | PostgreSQL 16; only the coordinator and workers can reach it |
| `desk-coordinator` | 1 replica: schedule, wake-ups, planning; waits for the database on start |
| `desk-worker` | 2 replicas, scale freely; the only pods with outbound HTTPS |
| `desk-web` | nginx serving `timeline.json` read-only at `heros-agent.space/data/market/` |

Secrets follow the node's convention for every agent (act, forge, play): one AWS Secrets Manager
secret, `market/prod`, read by the node's IAM role through External Secrets into the k8s secret `desk`.

| Property | What |
|---|---|
| `db-password` | generated by the release script the first time, kept after that; the DSN is built from it in-cluster |
| `llm-api-key` | `QWEN_LLM_API_KEY_V2`, copied from `../.ENV` on each release when it changed. If it's empty, the analyst uses the baseline |

The script also keeps a `MarketSecretsRead` inline policy on the node role, scoped to `market/*`.
Secret values pass through 0600 temp files only, never through arguments, output or the SSM command.

After rollout the script starts one refresh, so the page has data without waiting for the next slot.
